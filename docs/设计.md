# mre（mysql-redis-extend）架构设计

> 阶段A：扩展核心（env 配置、mysqlnd 捕获、redis 嗅探、日志写入、GA 编译）。
> 本文记录实现原理、关键取舍与下一阶段（yaml 规则 / 脚本回调 / 全局事务）的规划。

## 1. 总体架构

```
用户态                       扩展内部                        输出
──────                      ────────                       ─────
mysqli / PDO_MYSQL ──► mysqlnd ──► [mre_mysql.c 方法表挂钩] ─┐
phpredis / Predis  ──► PHP streams ──► [mre_redis.c ops 包装] ─┤──► [mre_log.c] ──► 文件/stdout/stderr//proc/1/fd/1
                                                            │        ▲
php.ini + 环境变量 ──► [mre_config.c env>ini 解析] ──────────┘        │
yaml 规则文件 ────────► [mre_yaml.c 内置解析器] ──(下一阶段规则)──────┘
```

生命周期：

- **MINIT**：注册 INI → 解析一次配置 → 安装 redis 工厂钩子与 mysqlnd 方法表钩子 → 加载 yaml。
- **RINIT**：重新解析配置（env 可能变）→ yaml 变更检测/热加载 → 钩子自愈（reassert / rehook）。
- **MSHUTDOWN**：还原工厂与方法表 → 释放 yaml 树 → 关闭日志句柄 → 注销 INI。

## 2. MySQL 捕获：mysqlnd conn_data + stmt 方法表覆盖

### 2.1 为什么选方法表覆盖

候选方案对比：

| 方案 | 结论 |
|---|---|
| mysqlnd conn_data 方法表覆盖（`mysqlnd_conn_data_set_methods` / `mysqlnd_stmt_set_methods`） | **采用**。这是 mysqlnd 官方暴露的插件级扩展点（`mysqlnd_ext_plugin.h`），位于 mysqli/PDO 之下，天然覆盖所有连接类；不需要改 PHP 核心。 |
| 官方 observer API | php-src 从未合并过正式的 query observer（历史上仅停留在 RFC/补丁），各版本无稳定 API，不可依赖。 |
| 钩 mysqli/pdo 函数表（`zend_function` 替换） | 太上层：每个用户类/对象 handlers 都要覆盖，且抓不到协议层信息（受影响行数、sqlstate），放弃。 |

### 2.2 实现要点

- **挂钩点**：`conn_data.query / store_result / use_result / next_result / dtor`，`stmt.prepare / stmt.execute / stmt.get_result`，结果对象实例级 `res->m.fetch_into`（全版本）与 `res->m.fetch_row`（仅 8.1+，见 §4）。
- **委托**：MINIT 时把当前（可能已被其他插件链接过的）方法表**整表拷贝**，保存被覆盖条目的原指针，调用前转发。方法表是 mysqlnd 在建连时通过 `data->m = mysqlnd_conn_data_get_methods()` 赋给每个连接的共享指针，因此 MINIT 里 set_methods 之后建立的所有连接都走我们的表；`RINIT` 每请求用一次指针比较自愈（防其他扩展后注册覆盖）。
- **每连接上下文**：通过官方插件机制 `mysqlnd_plugin_register()` 拿到 plugin_id，用 `mysqlnd_plugin_get_plugin_connection_data_data(conn, id)` 获得挂在连接对象尾部的槽位（连接分配时已按 plugin_count 预留，`pecalloc` 清零），存放"最近 SQL、采样预算、行数"等状态，随连接释放（`dtor` 钩子里 `pefree`，持久标志跟随 `conn->persistent`），无泄漏、无线程问题。
- **数据取用**：
  - SQL：`query(conn, query, len)` / `stmt_prepare(stmt, query, len)` 入参原文；
  - 影响行数：`conn->upsert_status->affected_rows`（`(uint64)-1` 表示"不适用"，如 SELECT 之后，日志中省略）；
  - 错误：`conn->error_info` / `stmt->data->error_info` 的 `error_no / error / sqlstate`；
  - 结果元信息：`res->field_count`、`res->m.num_rows(res)`（缓冲结果），非缓冲置 `truncated`；
  - 行采样：包装 `res->m.fetch_into`（mysqli 全部取行路径、PDO 8.1+ 的 `fetch_row` 也走它）与 `res->m.fetch_row`（8.1+，覆盖 PDO 的 `mysqlnd_fetch_row_zval`）。采样只读行数组的前 N 行（`mre.sample_rows`），格式化为 `a|b|c` 摘要，不动结果游标、不影响业务取行。

### 2.3 已知限制

- PDO 在 7.4/8.0 的缓冲结果行抓取走 C 数组路径（`m.fetch_row` 的 `void*` 参数在 7.4/8.0 存在 stmt 绑定取行复用同一槽位的类型歧义，为安全起见不包装），因此 7.4/8.0 上 PDO 只记元信息不采样行内容；8.1+ 起所有 `m.fetch_row` 调用点均为 `zval**`，安全覆盖。
- 异步 API（`send_query/reap_query` 直用）、`multi_query` 的首个结果之外的 use/store 已覆盖，`more_results` 布尔查询不单独记日志。
- mysqlnd 以独立 `mysqlnd.so` 分发的发行版（Debian/Ubuntu 包）必须先加载 mysqlnd 再加载 mre（README 已写明），因为插件区 getter 是数据符号，dlopen 时即需解析。

## 3. Redis 捕获：streams 传输层嗅探

### 3.1 为什么在 streams 层做

要求"不管哪种类都支持"。phpredis（`Redis`/`RedisCluster`）是 C 扩展，其 socket 通过 `php_stream_xport_create()` 创建；Predis 是用户态类，走 `fsockopen`/`stream_socket_client`，最终同样进入 `php_stream_xport_create()`。两者在 PHP 内的唯一公共汇合点就是 **streams 传输层**：

```
phpredis ──────────────┐
                       ├──► php_stream_xport_create("tcp://host:port") ──► xport_hash["tcp"] 工厂
fsockopen/stream_socket_client ─┘
```

因此覆盖了传输层就覆盖了所有"连接类"。`tls://`、`ssl://`、`unix://` 是独立协议名，不属于本阶段嗅探范围。

### 3.2 实现要点

- **工厂包装**：MINIT 用 `php_stream_xport_get_hash()` 取出当前 `"tcp"` 工厂（可能是内置的 `php_stream_generic_socket_factory`，也可能是 openssl 注册的 ssl 感知工厂）保存为原工厂，再 `php_stream_xport_register("tcp", mre_tcp_factory)`。我们的工厂**始终原样委托**原工厂建连（保留 bindto 等流上下文与 openssl 行为），仅当协议为 `tcp` 且 `resourcename` 解析出的端口等于 `mre.redis_port` 时，对该返回的 stream 做包装。`RINIT` 每请求检查 hash 内指针是否仍是我们，若被后加载的扩展（如 openssl）覆盖则重新注册（自愈）。
- **ops 包装**：把 `stream->ops`（`php_stream_socket_ops` 等）整结构拷贝到一块**随 stream 持久性一致分配**的内存（`pemalloc(size, stream->is_persistent)`），改写 `write/read/close` 三个入口，`stream->ops` 指向拷贝。持久化连接（pconnect / persistent id）在复用时不经过工厂，包装随流存活、语义正确。`close` 包装先调用原 close、**恢复 `stream->ops` 原指针后再释放包装内存**（引擎在 close 返回后仍可能读 `stream->ops`，否则构成 use-after-free——开发期实测踩过并已修复）。
- **RESP 双向增量解析**（纯状态机，可处理任意分包/粘包）：
  - 请求方向（write）：`*N` → 逐个 `$len` 参数，参数按字节计数精确消费（二进制安全），拼成 `CMD arg1 arg2 ...` 摘要；首字节非 `*` 的旧式 inline 命令按行记录。
  - 响应方向（read）：`+ - :` 行回复、`$len` bulk（内容截断摘要）、`$-1` null、`*N` 数组（记 `*N` 条数摘要，用深度栈处理嵌套数组）。每个顶层回复一条日志。
  - 全部为有界缓冲 + 截断标记，嗅探是旁路行为：解析异常只影响日志完整性，不影响连接与业务数据。
- **发送顺序语义**：write 包装在原 write 成功后记录（记录"实际发出的字节"），read 包装在原 read 成功后记录。

### 3.3 局限（与 README 一致）

- 不覆盖 `tls://` / `ssl://` 的 redis（它们注册的是 openssl 工厂、协议名不同）与 unix socket redis。
- phpredis 的 `pconnect` 持久连接在**首次**建连时被包装并随流存活，行为正确；但嗅探开关/端口配置在连接建立后改变，不影响已存在的持久流。
- 数组回复不展开元素内容（只记条数），业务上等价信息可用 bulk 摘要覆盖大多数命令（GET/SET/HGETALL 的元素等为 bulk）。
- 客户端若使用 pipeline，多条命令仍逐条解析记录（按 RESP 边界），回复按回复边界逐条记录。

## 4. 版本兼容策略（7.4 / 8.0 ~ 8.4）

所有差异集中在少量 `PHP_VERSION_ID` 分支，且**每个分支点都对照 php-src 各分支源码逐一核实过**（7.4 / 8.0 / 8.1 / 8.2 / 8.4）：

| 差异点 | 版本边界 | 处理 |
|---|---|---|
| `conn_data::store_result / use_result` 的 `flags` 参数 | 8.0 有、8.1 起移除 | `#if PHP_VERSION_ID < 80100` 双签名 |
| `res::fetch_into` 的 `enum_mysqlnd_extension ext` 尾参 | 同上 | 同上（含 `ZEND_FILE_LINE_DC` 宏，debug/非 debug 均匹配 typedef） |
| `res::fetch_row` 参数类型 `void*` → `zval**` | 8.1 起 | 仅 8.1+ 包装（7.4/8.0 有 stmt 绑定取行复用 `void*` 的类型歧义，不包装更安全） |
| `zend_register_ini_entries` 返回值/签名演变（8.2 起 `zend_result`，`_ex` 带 module type） | 8.2 起 | 统一使用 `REGISTER_INI_ENTRIES()` / `UNREGISTER_INI_ENTRIES()` 宏，跨版本安全 |
| INI 定义宏（`PHP_INI_ENTRY`，位于 `main/php_ini.h`） | 无差异 | 直接使用 |
| 模块全局宏（`ZEND_DECLARE_MODULE_GLOBALS` 等）、`ZEND_MODULE_GLOBALS_ACCESSOR` | 无差异 | 用引擎宏，ZTS/非 ZTS 自动正确 |
| `php_stream_transport_factory` typedef、`php_stream_xport_get_hash`、`php_stream_generic_socket_factory` 导出 | 无差异（已核对 7.4 与 8.4 头文件 diff） | 直接使用 |
| `mysqlnd_plugin_register(void)` / xetters / plugin area | 无差异（7.4/8.2/8.4 一致） | 直接使用 |
| `config.h` 引入位置 | — | 统一在 `php_mre.h` 顶部 `#ifdef HAVE_CONFIG_H` 引入，保证各编译单元的 `HAVE_MRE_MYSQLND` 一致（否则出现符号缺失） |

线程安全：全部共享状态使用模块全局（`MRE_G`，ZTS 下为线程本地）；跨请求生命周期内存一律 `pemalloc/pestrdup(…, 1)`（日志句柄路径缓存、yaml 树、redis ops 包装、mysql 连接上下文），请求级内存一律 `emalloc` 家族，避免请求结束时被 MM 回收后再次释放（开发期实测修复：`estrdup` 缓存日志路径导致退出时 double free）。

## 5. 日志子系统

- 单条日志、进程内句柄缓存：目标变更时才重开；`stdout`/`stderr` 特殊值不缓存；常规路径 `fopen(…, "a")` + 每条 `flock(LOCK_EX) → fwrite → fflush → flock(UN)`，fpm 多进程并发安全。
- `/proc/1/fd/1`：按普通文件 open append，容器内（root）等价写 pid1 的 stdout，被 `docker logs` 收集；打开失败降级 stderr 并**每进程只告警一次**（`mre.log_file` 为空同样告警一次并走 stderr），不会反复刷屏或崩溃。
- 父目录自动创建（`mkdir -p` 语义）。
- 写路径不分配 Zend 内存、只用栈缓冲——保证在 mysqlnd/streams 钩子内、甚至 shutdown 期间调用都安全。
- JSON 输出手工转义（引号/控制字符），UTF-8 原样透传。

## 6. 下一阶段规划（阶段B/C，本阶段已预留的接入点）

### 6.1 yaml 规则引擎

- 已具备：`mre.yaml_config` 配置读取、内置解析器（映射/序列/引号标量/块标量/注释、tab 报错、mtime 热加载）、`mre_yaml_dump()` 调试导出、树访问器 `mre_yaml_map_get()/mre_yaml_scalar()`。
- 计划：每次 `mysql/redis` 记录产生时，把记录（type/dir/content/extra）喂给规则匹配器：按 `rules: [{match: 正则, log: 路径}, ...]` 顺序匹配（正则用 PCRE API `pcre_exec`），命中即改写该条日志的目标文件；未命中走 `log_file` 默认。正则编译结果随 yaml 树缓存，文件 mtime 变化时整体重建。
- 建议 yaml 顶层结构（解析器已支持该写法）：

```yaml
rules:
  - match: "^SELECT .* FROM users"
    log: "/var/log/mre/sql-users.log"
  - match: ".*"
    log: "/var/log/mre/sql-default.log"
```

### 6.2 脚本回调日志路径

- 计划：规则可声明 `script: /path/resolve.php`；命中时以 `zend_call_function` 调用该 PHP 文件（`zend_execute` include 语义），向其提供超全局环境（`$_SERVER`、`$_POST`、`$_GET`、header 快照——fpm 下直接读 `SG(request_info)`），脚本 `return` 字符串作为该条日志的目标路径；脚本抛错/超时（按微秒计时的软超时保护）时回退规则 `log`。
- 接入点：`mre_log_write()` 增加一个"目标解析钩子"参数（记录上下文结构体），日志层仅按解析结果选 `FILE*`，保持现有 flock/缓存机制不变。

### 6.3 跨 fpm 全局事务（设计思路，已预留 `mre.state_dir`）

目标：业务通过命令开启一个"全局事务"后，**任意 fpm 进程、任意 mysql 连接**后续开启的普通事务都归属其中，最后由一次命令统一提交或回滚。

推荐实现：**状态文件注册表 + flock + 各进程下次 mysql 调用时检查回滚标记 + 延迟 commit**：

1. **注册表**：`mre.state_dir/gtid.json` 记录 `{state: active|mark_rollback|mark_commit, seq, start_time, owner}`；用 `flock` 保护读写（与日志同一套 libc flock 手法）。开关命令通过一个极小的用户态函数（下一阶段新增 `mre_gtxn_begin()/mre_gtxn_commit()/mre_gtxn_rollback()`）直接改写注册表。
2. **归属**：各 fpm 进程在 RINIT 读一次注册表快照；mysqlnd `conn_data::tx_begin / query("START TRANSACTION")` 钩子检测到 `state=active` 时，把该连接登记进注册表的成员列表（flock 下 append），同时把连接的真实 `autocommit` 交给 mysqlnd 正常语义，业务事务照常执行。
3. **延迟 commit**：业务调用 `commit` 时若全局事务处于 `active`，钩子把该连接标记为"待提交"并把提交动作推迟——实现上推荐**在注册表标记 `state=precommit` 后由各成员连接的下一次 mysql 调用前检查并统一执行**，避免长持有锁；也可以选择更强一致性的"协调者直接对成员连接 socket 发 COMMIT"，但那需要跨进程操作连接 fd，复杂度高，不建议第一版做。
4. **回滚**：`mre_gtxn_rollback()` 只需把注册表标记为 `mark_rollback`；**每个成员连接在它的下一次 mysql 调用入口**（`query/prepare/execute` 钩子开头）检查标记，发现 `mark_rollback` 先对该连接发 `ROLLBACK` 再放行本次调用——这保证不依赖跨进程通知机制，任何 fpm 进程在下次碰库时自然完成回滚，flock 读标记的开销为每连接每次调用一次文件读（可进程内缓存 + mtime 校验）。
5. **崩溃安全**：注册表写入采用 `临时文件 + rename` 原子替换；成员列表里的连接随进程死亡自然失效（其未提交事务由 MySQL 服务端在连接断开时回滚），注册表 `seq` 递增避免旧注册表被误认。
