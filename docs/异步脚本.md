# 异步脚本（mre.log_script_async）

本文是 `mre.log_script_async` / `MRE_LOG_SCRIPT_ASYNC` 的部署与使用说明。
实现原理与取舍见 [设计.md](设计.md) §9；同步脚本（`mre.log_script`）的契约见
[README](../README.md)「脚本回调」一节——**同步路径行为完全不变**。

## 1. 一句话

配置 `mre.log_script_async` 后，扩展**不再写任何日志文件**：每条记录先由扩展渲染成
最终整行，然后 fork 一个子进程去执行 PHP 脚本；请求线程 fork 完立即返回，脚本自己
负责 `flock + fwrite` 落盘。脚本里做的事（HTTP 推送、慢磁盘、复杂路由）不再占用
业务请求时间。

## 2. 配置与生效优先级

| ini | env | 默认 | 说明 |
|---|---|---|---|
| `mre.log_script_async` | `MRE_LOG_SCRIPT_ASYNC` | 空 | PHP 脚本绝对路径；空 = 关闭异步 |

生效规则（`mre_log_write` 内的分支顺序）：

```
mre.enable = 0                      -> 不记录
mre.log_script_async 非空           -> 异步：fork 子进程执行脚本；扩展不落盘
mre.log_script 非空                 -> 同步脚本回调（旧行为）
yaml 规则命中                       -> 规则指定的文件（旧行为）
mre.log_file 非空                   -> 主日志（旧行为）
否则                                -> stderr + 每进程一次告警（旧行为）
```

要点：

- 异步配置**优先于**同步脚本：两者同时配置时只走异步，`mre.log_script` 被忽略。
  迁移期间请只保留一个（见 §7）。
- 异步模式下 `mre.log_file` 也不参与：扩展不写文件。只有"异步无法运行"的告警会走
  主日志（`mre.log_file` 或 stderr），那是告警、不是记录。

php.ini 示例：

```ini
mre.enable = 1
mre.log_format = json

; 异步（推荐：脚本自己写文件，扩展不落盘）
mre.log_script_async = "/opt/mre/scripts/mre_log_router.php"

; 想保留一个兜底主日志用于排障告警（异步模式不写记录，只写告警）：
; mre.log_file = "/var/log/mre/mre-main.log"
```

docker 环境变量：

```bash
docker run \
  -e MRE_ENABLE=1 \
  -e MRE_LOG_SCRIPT_ASYNC=/opt/mre/scripts/mre_log_router.php \
  -e MRE_LOG_FORMAT=json \
  your-php-image
```

验证配置已被识别：

```bash
php -i | grep -E "log_script(_async)? \(MRE_LOG_SCRIPT"
```

## 3. 机制（父进程到底做了什么）

每条记录：

1. **父进程（业务请求）**：`mre_log_format_line()` 渲染出最终一行（json 或 text，
   不含结尾换行）→ 机会性回收**自己记录的第一层子进程**（`waitpid(pid, WNOHANG)`，
   不阻塞）→ 捕获一次本进程 pid（供 `$context['pid']` 与失败节流共用）→ `fork()` →
   立即 `return`。不等待子进程、不改 `SIGCHLD`、绝不用 `waitpid(-1, ...)`。
2. **第一层子进程**：再 `fork()` 一次后立刻 `_exit(0)`。
3. **孙进程**：构建 `$context`（同步字段 + `line` + `format`）→ 执行脚本 →
   `_exit(0)`。只允许 `_exit()`，不会跑 RSHUTDOWN/destructor、不会 flush 父进程的
   stdio 缓冲。

因此调用方（mysqli/PDO/redis 钩子）只多付一次格式化 + 两次 `fork()` 的系统调用开销，
不会因为脚本里的网络/磁盘等待而变慢。

> 为什么行由扩展渲染：`pid`/`request_id`/`time` 是请求级字段，必须在 fork 之前取定；
> 同时让"扩展自己写"和"脚本写"共用同一份格式代码，异步与同步日志逐字节一致。

## 4. `$context` 字段表

同步路径的全部字段原样保留（同步模式不会出现 `line`/`format`）：

| 键 | 类型 | 说明 |
|---|---|---|
| `type` | string | `mysql` 或 `redis` |
| `dir` | string | `req` 或 `resp` |
| `content` | string | SQL 或 redis 命令/响应文本 |
| `extra` | array | 行数/错误/耗时等结构化字段（`cmd`/`affected_rows`/`rows`/`fetched_rows`/`fields`/`stmt_id`/`error_code`/`error`/`sqlstate`/`host`/`port`/`truncated`/`prepared`/`sql_full`/`time_end`/`cost_ms`，仅含存在项） |
| `headers` | array | 当前 HTTP 请求 header（小写连字符名 => 值；CLI 为 `[]`） |
| `post` | array | `$_POST` 原样 |
| `cookie` | array | `$_COOKIE` 原样 |
| `get` | array | `$_GET` 原样 |
| `session_id` | string | `session_id()` 的值（未启动为空串） |
| `uri` | string | `$_SERVER['REQUEST_URI'] ?? ''` |
| `method` | string | `$_SERVER['REQUEST_METHOD'] ?? ''` |
| `pid` | int | 请求进程 pid（与日志行 `pid` 一致，**不是**子进程 pid） |
| `request_id` | string | `<pid>-<请求序号>`（与日志行一致） |
| `script` | string | 当前请求入口脚本路径（路由脚本据此识别项目根） |
| **`line`** | **string** | **仅异步**：扩展已渲染好的整行日志（json 或 text，**不含结尾换行**）。脚本直接追加即可 |
| **`format`** | **string** | **仅异步**：`json` 或 `text`（与 `line` 对应） |

`$_SERVER` 等超全局原样可读（扩展只读不写）。异步模式下脚本的**返回值被忽略**——
扩展不关心脚本写到哪、也不做二次落盘。

> `pid` 的实现细节：异步路径在 `fork()` **之前**取一次请求进程 pid（即 fpm worker），
> 通过 `mre_script_ctxinfo.pid` 传给公共的 `$context` 构建函数；孙进程自身的
> `getpid()` 与日志行 pid 不同，不会被用于该字段。同步路径该字段置 0，构建时仍取
> 当前进程 pid，行为不变。

## 5. 脚本职责

异步模式下，日志的**全部**落盘责任在脚本侧：

1. 选路径（路由脚本：项目根 + URL 路径 + query/write/redis 分类）；
2. 目录不存在先 `mkdir`；
3. `flock(LOCK_EX)` + `fwrite($context['line'] . "\n")` + `fflush` + `flock(LOCK_UN)`；
   多 fpm worker 并发写同一文件靠这把锁串行化（与扩展的写入器语义一致）；
4. 不做长阻塞（脚本跑在孙进程里，虽不影响请求，但会占用进程槽位）；
5. 自己处理业务层失败（异步模式下扩展只在脚本执行失败时打一行节流的 stderr，
   见 §6，不会重试、也不会回落同步）。

最小示例：

```php
<?php
// mre.log_script_async 指向本文件
$line = isset($context['line']) && is_string($context['line']) ? $context['line'] : null;
if ($line === null) {
    return null; // 万一被同步模式 include：不重复写
}
$file = '/var/log/mre/async.log';
$dir = dirname($file);
if (!is_dir($dir)) {
    @mkdir($dir, 0755, true);
}
$fp = @fopen($file, 'ab');
if ($fp !== false) {
    if (flock($fp, LOCK_EX)) {
        fwrite($fp, $line . "\n");
        fflush($fp);
        flock($fp, LOCK_UN);
    }
    fclose($fp);
}
return null; // 异步模式返回值被忽略
```

仓库自带脚本无需重写：

- `scripts/mre_log_router.php`：检测到 `$context['line']` 即进入"自写模式"，
  在原有路由结果上自己 `flock + fwrite(line."\n")`，返回值行为保持不变；
- `scripts/mre_oo_log_script.php`：include 上面的 router，自动获得自写能力；
  OpenObserve 推送逻辑不变（现在跑在孙进程里，不再占用请求时间）。

## 6. 故障与降级（丢弃优先）

异步模式的唯一目标是"不阻塞请求"，所以任何无法异步的场景都**丢弃该条记录**，
绝不回落同步、绝不阻塞：

| 场景 | 行为 |
|---|---|
| `fork()` 失败 | 每进程一次 `type:"warn"` 告警（写主日志或 stderr），该条丢弃 |
| ZTS 构建（Apache worker mpm 等线程化 SAPI） | 同上（首次使用时告警一次）；NTS 的 fpm 不受影响 |
| RSHUTDOWN 之后 / executor 已关闭 | 每进程一次性告警并丢弃（告警写主日志，不经过脚本） |
| 脚本内部再触发 SQL/redis（递归） | 孙进程有 `script_busy` 标志，直接丢弃、不再 fork |
| 孙进程 `EG(active)==0` | 静默 `_exit(0)`（脚本尚未执行，无可报告） |
| 脚本不存在（`stat` 失败） | 向 **stderr** 打一行（摘要 `stat() failed`，每 worker 60 秒节流），记录丢弃 |
| 脚本抛异常 / 解析错误 | 异常在用户态被 catch，摘要经 stderr 报出（每 worker 60 秒节流），记录丢弃、脚本不影响业务请求 |
| 包装串编译失败 | 同上（摘要 `wrapper compile failed`；实践中不可达） |
| 脚本内 `exit()`/致命错误 | bailout 被孙进程内层捕获，记录丢弃（`exit()` 是脚本主动行为，不算失败，不告警） |

### 6.1 可观测性：失败走 stderr，每 worker 60 秒节流

异步失败不再完全静默。孙进程发现脚本执行失败时向 **stderr** 打一行（fpm 会把它
落到自己的 error log），文案固定为：

```
[mre] async log_script '<脚本路径>' failed (<摘要>); record dropped
```

- 摘要来源：包装串 catch 到的异常/ParseError 的 `getMessage()`（截断到 255 字节）、
  或 `wrapper compile failed`、或 `stat() failed`。
- **每 worker 每 60 秒最多一条**：标记文件**按分钟分桶**
  `/tmp/.mre-async-warn-<worker pid>-<bucket>`（`bucket = time(NULL) / 60`），
  用 `open(O_WRONLY | O_CREAT | O_EXCL, 0600)` **原子抢占**：创建成功的那一个孙进程
  才打印，`errno == EEXIST` 表示本窗口已被同 worker 的另一个孙进程报过，直接静默。
  因此同一毫秒内并发失败（例如同时 fork 出的两个孙进程都失败）也只有一行。
  文件名里的 pid 是 `fork()` 之前取到的 worker pid（孙进程的 `getppid()` 是第一层
  子进程，不能代表 worker）。
- 其他 `open` 失败（如 `/tmp` 不可写）：**仍打印这一行**（宁可多报，不要静默），
  且不重试。
- 标记文件只在失败时产生：每 worker 每 60 秒最多一个空文件，内容为空，`/tmp`
  由系统自行清理。
- 只 `write(2)` 直写、不重试、不阻塞；写失败也无所谓（记录已经丢了）。
- 因此"记录丢失"仍需要目标日志 + fpm error log 一起看：前者少行、后者有上面这行，
  就是脚本执行失败。需要"记录绝不丢"的场景请继续用同步 `mre.log_script`。

## 7. 迁移：同步配置 → 异步配置

脚本本身不用重写（自带 router 已内置自写模式），只改配置键名：

### 7.1 迁移前（同步）

```ini
mre.enable = 1
mre.log_script = "/opt/mre/scripts/mre_log_router.php"
; 或 MRE_LOG_SCRIPT=/opt/mre/scripts/mre_log_router.php
```

### 7.2 迁移步骤

1. **备份配置**：记录当前 `mre.log_script`（或 `MRE_LOG_SCRIPT`）的值与脚本路径。
2. **确认脚本支持自写模式**：
   - 用仓库自带 `scripts/mre_log_router.php`（含 `mre_oo_log_script.php`）→ 直接可用；
   - 自研脚本 → 按 §5 增加 `isset($context['line'])` 分支（或先改用自带 router）。
3. **改配置**：删除/注释 `mre.log_script`（或 `MRE_LOG_SCRIPT`），新增
   `mre.log_script_async = "<同一脚本路径>"`（env 同理），其余配置不动。
4. **重启 fpm / 重新加载 PHP**（ini/env 在 RINIT 解析，`kill -USR2` 重载 fpm 即可）。
5. **验证**：
   - `php -i | grep log_script_async` 能看到新路径；
   - 业务触发一条 SQL，确认目标日志文件出现新行，且行内容与旧同步格式一致
     （`line` 就是扩展原本会写的字节）；
   - 观察 `ps`：应看到短暂出现的子进程/孙进程，而不是阻塞的请求；
   - 若日志没出现，检查：脚本是否判断了 `$context['line']`、目标目录权限、
     `mre.enable`、是否还有旧的 `mre.log_script` 与之冲突。
6. **回滚**：把配置键改回 `mre.log_script` 并重载即可——脚本两种模式都支持，
   无需改代码。

> Docker/K8s：把 `MRE_LOG_SCRIPT` 换成 `MRE_LOG_SCRIPT_ASYNC`（值不变）后重建容器
> 或热重载；不要同时设置两个变量。

## 8. 代价与风险

- **每条记录一次 fork（实际两次）**：`fork()` 的固定系统调用/页表复制成本随 QPS
  线性增长；极高 QPS 下会明显增加内核 CPU。需要"零 fork"的场景不适合异步模式。
- **僵尸与 reaper 行为**：孙进程由 init 回收；第一层子进程的父进程是 fpm worker，
  退出后**会一直以僵尸形式留在 worker 名下**（僵尸不会自己消失，"短僵尸"是错误
  描述：高频下进程表会被打满、`fork()` 返回 `EAGAIN`、记录全丢）。扩展因此维护一个
  **32 项静态 pid 数组**（只记自己 fork 的第一层子进程），每次写记录、`fork` 之前
  机会性 `waitpid(pid, WNOHANG)` 回收：回收成功或 `ECHILD` 就移除并压缩数组，返回 0
  则保留。数组满时覆盖最旧项——极端突发下可能漏掉一个僵尸，但不会无限累积。
  仍然不改 `SIGCHLD`、绝不 `waitpid(-1, ...)`（会收走业务 `proc_open`/`exec` 的子
  进程）。稳态下数组只有 0~1 项，等于每条记录多一次 `waitpid` 系统调用。
- **子进程不得依赖请求级状态**：孙进程只持有 fork 时刻的内存快照（连接、锁、流、
  请求级对象都可能已过期）。脚本应只做"读 `$context` → 选路径 → 打开文件 → 追加"
  这类自包含动作；不要在脚本里复用业务连接/全局状态。
- **脚本异常只影响子进程**：不会让请求失败，但该条记录丢失且不会自动重试；
  扩展对该异常静默（不写主日志，避免子进程回写父进程日志造成 pid 错位/竞争）。
- **variance**：同一请求的多条记录由不同子进程写入，落盘顺序不保证与请求内顺序
  完全一致（目标行本身仍完整、逐字节正确）；需要严格时序时请用同步模式或脚本侧
  加序列字段。
- **ZTS 环境不可用**：异步路径在 ZTS 构建下编译为空实现（一次性告警 + 丢弃）。
- **opcache / 脚本编译**：每条记录在孙进程里 `include` 一次脚本；启用 opcache 时命中
  共享内存缓存，否则每条记录多付一次脚本编译（建议生产开启 opcache）。
- **CLI/短请求**：请求在孙进程完成前就可能结束；孙进程继续执行并自行退出，
  其输出被 ob 捕获丢弃，不影响父进程。
